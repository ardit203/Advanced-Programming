# Chapter 2 - Exceptions

Usually, when solving certain problems, it is necessary to develop two separate strategies.
The first strategy refers to the desired course of events, when the problem is being solved according to the planned approach and the execution of partial activities proceeds as expected.
The second strategy refers to anticipating and resolving situations that do not align with the desired course of events. Most often, this strategy deals with handling exceptional situations that may occur while solving problems.

This approach can be completely applied when solving software tasks.
Many programming languages offer direct support for dealing with such so-called exceptional situations that a program may encounter. This is done through the exception mechanism.

Exceptions are events that occur during the execution of programs and alter their normal flow (for example, division by zero, accessing an array element outside its bounds, etc.).
In Java, an exception is an object that encapsulates information about an error that occurred in a method and contains:
- Information about the error, including its type
- The state of the program before the error occurred
- Other additional information

An exception can be thrown in a given method and caught so that it can be handled properly and on time.
Exceptions are used to describe many different types of error conditions.

Exceptions separate the error-handling code from the regular code.
Using exceptions ensures cleaner and more readable code. With exceptions, errors are propagated — meaning that nested methods don’t need to handle errors explicitly, which leads to less work and more reliable code.

Defining exception classes allows grouping types of errors according to their parent class and/or identifying them by their actual class.
In other words, exceptions standardize error handling within programs.

In the Java programming language, an exception is an object that is always an instance of a class derived from `Throwable`.
Java defines several types of exceptions within its built-in libraries.
In addition, Java allows users to define their own types of exceptions if the built-in ones do not meet their needs.

## 2.1 Built-in Exceptions

The built-in exceptions are available in Java’s standard libraries. These exceptions are useful for describing specific situations in which errors occur. Below is a list of important built-in exceptions in Java:
- `ArithmeticException` — thrown when an exceptional condition occurs during an arithmetic operation.
- `ArrayIndexOutOfBoundsException` — thrown to indicate that an array has been accessed with an invalid index. The index is either negative or greater than or equal to the size of the array.
- `ClassNotFoundException` — thrown when an attempt is made to access a class whose definition cannot be found.
- `FileNotFoundException` — thrown when a file is not available or cannot be opened.
- `IOException` — thrown when an input/output operation fails or is interrupted.
- `InterruptedException` — thrown when a specific thread is waiting, sleeping, or processing, and it gets interrupted.
- `NoSuchFieldException` — thrown when a specified class does not contain the requested field (or variable).
- `NoSuchMethodException` — thrown when there is an attempt to access a method that does not exist.
- `NullPointerException` — thrown when there is an attempt to access an object that is null.
- `NumberFormatException` — thrown when a method cannot convert a string into a numeric format.
- `RuntimeException` — represents any exception that occurs during the execution (runtime) of a program.

## 2.2 User Defined Exceptions

The code being executed may encounter a problem that cannot be described using the standard (`built-in`) exception classes.
In such a case, the user needs to define their own type of exception by extending the `Exception` class or any other class that directly or indirectly inherits from `Exception`.
Typically, the custom exception class should implement the default constructor and an overloaded constructor that includes all the details about the problem the user wants to convey.

> ### Problem 2.3
> A system needs to be developed for online pizza ordering.
> The menu of the pizzeria consists of the following items:
> - Pizza:
>   - Standard: $10
>   - Pepperoni: $12
>   - Vegetarian: $8
> - Extra:
>   - Ketchup: $3
>   - Coke: $5
>
> To represent the menu, each item must implement the `Item` interface, which describes a single menu item and defines the following method:
> - `int getPrice()` – returns the price of the specific item.
>
> Next, you need to define two classes, `ExtraItem` and `PizzaItem`, so that a distinction can be made between pizzas and other items in the order. Both classes should have one constructor that takes a single `String` argument:
> - `ExtraItem(String type)` – valid values for `type` are `Coke` and `Ketchup`
> - `PizzaItem(String type)` – valid values for `type` are `Standard`, `Pepperoni`, and `Vegetarian`
>
> If an invalid value (not on the menu) is passed for type, an exception should be thrown:
> - `InvalidExtraTypeException` for extras
> - `InvalidPizzaTypeException` for pizzas
>
> Finally, you need to implement the `Order` class, which provides the following functionalities:
> - `Order()` – creates a new empty order.
> - `addItem(Item item, int count)` – adds the specified item to the order.
>   - The parameter count indicates how many units of the given item are ordered.
>   - If count is greater than 10, throw an `ItemOutOfStockException(item)`.
>   - If the item already exists in the order, it should be replaced with the new one (not added again).
>   - The below code results in an order containing one Standard pizza (since the previous one was replaced).
>
>           Order order = new Order();
>
>           order.addItem(new PizzaItem("Standard"), 2);
>
>           order.addItem(new PizzaItem("Standard"), 1);
>
> - `getPrice(): int` – returns the total price of the order.
> - `displayOrder()` – prints the content of the order with line numbers before each item, the name of the item, the quantity, the total price for that item, and the total price of the whole order. The formatting should follow these rules: the line number occupies 3 spaces and is right-aligned, the item name occupies 15 spaces and is left-aligned, the quantity occupies 2 spaces and is right-aligned, and the price for each item occupies 5 spaces and is right-aligned. The word “Total:” occupies 22 spaces and is left-aligned, while the total order price occupies 5 spaces and is right-aligned. 
> Example:
>
>           1. Standard          x 2   20$
>
>           2. Vegetarian        x 1    8$
>
>           3. Coke              x 3   15$
>
>        Total:                       43$
>
> The order of the items displayed should match the order in which they were added to the order. If an item is added again, its position in the list does not change.
> - `removeItem(int idx)` – removes the item at the given index (all items with higher indexes shift left). If there is no item with such an index, throw an `ArrayIndexOutOfBoundsException(idx)`.
> - `lock()` – locks the order. To lock the order, there must be at least one item in it; otherwise, throw an `EmptyOrderException`. 
>
> Once locked, the order cannot be modified using `addItem` or `removeItem`. Calling these methods after locking should throw an `OrderLockedException`.



When solving problems where there is a possibility of an unexpected course of events, it is necessary to use the mechanism for throwing and handling exceptions. When solving such problems, it is important to:
1. Identify where in the code an unexpected event might occur, and then create and throw an exception at the appropriate place.
2. Wrap the call to potentially risky code (such as a method or constructor) inside a `try/catch` block to define the program’s behavior in case an exception occurs. It should also be noted that interpreters and most development environments automatically provide suggestions about which parts of the code need to include this block.

```java
import java.util.ArrayList;
import java.util.Optional;
import java.util.Scanner;
import java.util.stream.IntStream;

interface Item {
    boolean isPizza();
    int getPrice();
    String getType();
}

enum ExtraType {
    Coke(0), OrangeJuice(1), Ketchup(2);

    private final int value;
    private final int cost;

    ExtraType(int value) {
        this.value = value;
        if (value == 0)      this.cost = 5;
        else if (value == 1) this.cost = 8;
        else                 this.cost = 3;
    }

    public int getCost()  { return cost; }
    public int getValue() { return value; }
}

enum PizzaType {
    Standard(0), Pepperoni(1), Extra_cheese(2), Vegetarian(3);

    private final int value;
    private final int cost;

    PizzaType(int value) {
        this.value = value;
        switch (value) {
            case 0:  this.cost = 10; break;
            case 1:  this.cost = 12; break;
            case 2:  this.cost = 15; break;
            default: this.cost = 8;  break; // Vegetarian
        }
    }

    public int getCost()  { return cost; }
    public int getValue() { return value; }
}

// Exceptions used by the order system

class EmptyOrder extends Exception {
    public EmptyOrder() { this("The order must not be empty"); }
    public EmptyOrder(String message) { super(message); }
}

class InvalidExtraTypeException extends Exception {
    public InvalidExtraTypeException(String type) { super(type); }
    public InvalidExtraTypeException()           { this("Nepoznat tip"); }
}

class ItemOutOfStockException extends Exception {
    private final Item item;

    public ItemOutOfStockException(Item item) { this.item = item; }
    public ItemOutOfStockException()          { this("Unknown item is out of stock"); }
    public ItemOutOfStockException(String message) { super(message); this.item = null; }

    public Item getItem() { return item; }
}

class InvalidPizzaTypeException extends Exception {
    public InvalidPizzaTypeException() { }
}

class OrderLockedException extends Exception {
    private static final long serialVersionUID = 1L;
    public OrderLockedException() { }
}

// Items

class ExtraItem implements Item {
    private final ExtraType type;

    public ExtraItem(String type) throws InvalidExtraTypeException {
        try {
            this.type = ExtraType.valueOf(type);
        } catch (IllegalArgumentException e) {
            throw new InvalidExtraTypeException(type);
        }
    }

    public ExtraItem(ExtraType type) { this.type = type; }

    @Override public int getPrice() { return type.getCost(); }
    @Override public boolean isPizza() { return false; }
    @Override public String getType() { return type.name(); }
}

class PizzaItem implements Item {
    private final PizzaType type;

    public PizzaItem(String type) throws InvalidPizzaTypeException {
        try {
            this.type = PizzaType.valueOf(type);
        } catch (IllegalArgumentException e) {
            throw new InvalidPizzaTypeException();
        }
    }

    @Override public int getPrice() { return type.getCost(); }
    @Override public boolean isPizza() { return true; }
    @Override public String getType() { return type.name(); }
}

// Order aggregate

class Order {
    private static class OrderItem {
        private final Item item;
        private int count;

        public OrderItem(Item item, int count) {
            this.item = item;
            this.count = count;
        }
        public Item getItem()   { return item; }
        public int  getCount()  { return count; }
        public void setCount(int count) { this.count = count; }
        public int  getPrice()  { return item.getPrice() * count; }
    }

    private final ArrayList<OrderItem> items;
    private boolean locked;

    public Order() {
        this.items = new ArrayList<>();
        this.locked = false;
    }

    public void addItem(Item item, int count)
            throws OrderLockedException, ItemOutOfStockException {
        if (locked) throw new OrderLockedException();
        if (count > 10) throw new ItemOutOfStockException(item);

        Optional<OrderItem> existing = items.stream()
                .filter(each -> each.getItem().getType().equals(item.getType()))
                .findFirst();

        if (existing.isPresent()) {
            existing.get().setCount(count); // replace count if already present
            return;
        }
        items.add(new OrderItem(item, count));
    }

    public void removeItem(int index) throws OrderLockedException {
        if (locked) throw new OrderLockedException();
        // Throw the exact type from the spec instead of List's IndexOutOfBoundsException
        if (index < 0 || index >= items.size())
            throw new ArrayIndexOutOfBoundsException(index);
        items.remove(index);
    }

    public int getPrice() {
        return items.stream().mapToInt(OrderItem::getPrice).sum();
    }

    public void displayOrder() {
        IntStream.range(0, items.size()).forEach(i -> {
            OrderItem oi = items.get(i);
            System.out.printf("%3d.%-15sx%2d%5d$%n",
                    i + 1, oi.getItem().getType(), oi.getCount(), oi.getPrice());
        });
        System.out.printf("%-22s%5d$%n", "Total:", getPrice());
    }

    public void lock() throws EmptyOrder {
        if (items.isEmpty()) throw new EmptyOrder();
        locked = true;
    }
}

// Test harness

public class PizzaOrderTest {
    public static void main(String[] args) {
        Scanner jin = new Scanner(System.in);
        int k = jin.nextInt();

        if (k == 0) { // test.txt order with removing
            Order order = new Order();

            while (true) {
                try {
                    String type = jin.next();
                    String name = jin.next();
                    Item item;
                    if (type.equals("Pizza")) item = new PizzaItem(name);
                    else                      item = new ExtraItem(name);

                    if (!jin.hasNextInt()) break;
                    int count = jin.nextInt();
                    order.addItem(item, count);
                } catch (Exception e) {
                    System.out.println(e.getClass().getSimpleName());
                }

                if (!jin.hasNext()) break;
            }

            if (jin.hasNext()) jin.next(); // consume token if present (mirrors original)
            System.out.println(order.getPrice());
            order.displayOrder();

            while (jin.hasNextInt()) {
                try {
                    int idx = jin.nextInt();
                    order.removeItem(idx);
                } catch (Exception e) {
                    System.out.println(e.getClass().getSimpleName());
                }
            }

            System.out.println(order.getPrice());
            order.displayOrder();
        }
        else if (k == 1) { // test.txt locking & exceptions
            Order order = new Order();

            try { order.lock(); }
            catch (Exception e) { System.out.println(e.getClass().getSimpleName()); }

            try { order.addItem(new ExtraItem("Coke"), 1); }
            catch (Exception e) { System.out.println(e.getClass().getSimpleName()); }

            try { order.lock(); }
            catch (Exception e) { System.out.println(e.getClass().getSimpleName()); }

            try { order.removeItem(0); }
            catch (Exception e) { System.out.println(e.getClass().getSimpleName()); }
        }

        jin.close();
    }
}

```


In this task, several situations can be identified where the expected flow of execution may be disrupted:

1. When creating objects of type `ExtraItem` or `PizzaItem`, the text received as an argument in their constructors must be converted into an object of the corresponding enumeration.
   This part of the code is wrapped in a `try/catch` block. If the `enum` object is successfully created, the corresponding `ExtraItem` or `PizzaItem` object will also be created.
   Otherwise, the `valueOf` method of the enumeration will throw an `InvalidArgumentException`, and the program will continue in the `catch` block defined for that type of exception.
   Inside this `catch` block, a user-defined exception (`InvalidPizzaTypeException` or `InvalidExtraTypeException`) will be thrown, stopping the creation of invalid objects.
   Therefore, an exception handling mechanism (`try/catch` block) must be provided everywhere the constructors of `ExtraItem` and `PizzaItem` are called.
   Generally, it is not considered good practice for constructors to throw exceptions — argument validation is usually done beforehand in separate validators — but for the sake of simplicity, in this case, it is done within the constructor itself.

2. In the `addItem` method, an exception of type `ItemOutOfStockException` is thrown when attempting to add an item with a quantity greater than 10.
   Accordingly, a mechanism for handling this exception (`try/catch` block) must be provided wherever the `addItem` method is called.

3. In the `Order` class, a boolean variable `locked` is stored, which is initially set to `false` (the order is open).
   However, when the `lock()` method is called, the order becomes locked — meaning that the `locked` variable is set to `true`.
   In the methods `addItem` and `removeItem`, an exception of type `OrderLockedException` must be thrown if the order is already locked.
   To handle this exception, calls to these methods should be wrapped in `try/catch` blocks.

4. In the `lock()` method, it is necessary to check whether the order contains at least one item.
   If the list of items is empty, an exception of type `EmptyOrderException` should be thrown.

5. When attempting to delete an order at a position outside the array’s boundaries, there are two possible cases:

   - If the data structure used for storing the orders is a regular array, the `removeItem` method should include a check to ensure that the index `idx` is within the range `0` to the size of the array.
     If not, an exception of type `ArrayIndexOutOfBounds(idx)` should be thrown.
   - If an `ArrayList` is used to store the orders, its access methods automatically throw an exception of type `ArrayIndexOutOfBounds` (already defined in the `java.lang` package).
     Handling this exception is the same for both approaches — by using a `try/catch` block wherever the `removeItem` method is called.
